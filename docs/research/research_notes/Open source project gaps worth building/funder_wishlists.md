# Funder and standards-body wishlists for open-source security (as of 22 October 2026)

Scope note: inbound vulnerability-report triage for maintainers and generic code scanners are excluded per assignment. Anything marked "[interpretation]" is my reading, not the funder's words. GitHub health figures (stars, last push, open issues) were pulled live from the GitHub API on 22 Oct 2026.

## Key Question 1: What do the funders explicitly name as gaps, priorities or RFPs in 2025-2026, and what are their windows, sizes and deadlines?

### Takeaway
Only two funders publish topic-specific "we want proposals on X" calls that are open right now: NLnet's new Open Internet Stack programmes (Restack and CodeSupply, EUR 5k-50k, deadline 3 Nov 2026) and Germany's Sovereign Tech Resilience programme (rolling, services in memory safety, post-quantum readiness, supply-chain security and CRA compliance). Alpha-Omega (USD 50k-100k typical, quarterly; Q4 submissions close 31 Oct 2026), the Sovereign Tech Fund (EUR 50k minimum, rolling) and the GitHub Secure Open Source Fund (USD 10k, rolling) fund maintainers of existing critical projects rather than new tools, but their 2026 statements converge on one gap: moving from AI-accelerated vulnerability discovery to actually shipping fixes.

## Key Question 2: What have OpenSSF working groups listed as open problems or wanted tooling in 2026?

### Takeaway
The clearest "wanted" items sit in working-group issue trackers rather than blog posts: the Vulnerability Disclosures WG wants maintainer security-contact discovery tooling, a PURL-searchable CVE database, a federated OSV-based "OSS VulnDB", VEX-creation tools for upstreams and AI-contribution policy templates; the Securing Software Repositories WG wants a package-repository threat model, a standard for onboarding Trusted Publishing identity providers and a Binary Transparency guide/spec; the AI/ML WG wants MCP/agent incident data and controls for SAFE-MCP, an "AI Vulnerability Disclosure SIG", and ways for "OpenSSF and similar security projects [to] surface their findings in ways that AI agents can use".

## Key Question 3: Which OWASP projects are listed as needed, incubating without a leader, or calling for contributors in 2026?

### Takeaway
OWASP publishes no "projects without a leader" list in 2026; the board committed to a 2026 "community-driven leadership campaign" and a project health triage, and the Project Committee maintains a short "projects seeking funding" list. ## Key Question 4: What did the "securing open source in the AI era" discussions name as unmet tooling needs beyond inbound report triage?

### Takeaway
Beyond triage, the named needs are: moving from discovery to shipped, validated fixes ("fix the bugs"); locally runnable models and harnesses so projects can scan their own code without uploading it; usable cyber reasoning systems outside competition infrastructure; and automated patch/dependency workflows for consumers. curl and the kernel both report that AI tools now find real bugs that other methods missed, while AI-written patches remain inferior to human fixes.

### Cited Findings
- Greg Kroah-Hartman, Kernel Recipes (LWN, 1 Oct 2026): "the tooling is able to scale to this level of activity"; maintainers should "run local models; they are good enough for the job, and non-public information should never be uploaded to a non-local system"; recommended Chris Mason's kres tool; reporters are asked to "submit an initial fix with their report"; there is "now funding for a full-time developer to work on reports sent to security@kernel.org"; the remaining job is to "fix the bugs" over "a rough 18 months". — [LWN](https://lwn.net/SubscriberLink/1096908/c6356cdf7f44d632/)
- Kernel CVE volume: "In the first six months of 2026, the kernel racked up 2,308 distinct CVE identifiers"; Linux 7.2 pushed CVEs per release past 1,500; Kroah-Hartman: "The number of llm-found issues is only on the rise right now, it's going to be a very long 18 months at the least to dig ourselves out of this mess". Policy: a bug found with AI tooling is treated as public and sent to subsystem maintainers. — [noze.it](https://www.noze.it/en/insights/432-linux-kernel-cves-two-days/); [Phoronix](https://phoronix.com/news/Linux-7.3-Rough-Cycle)
- Kroah-Hartman (7 Apr 2026) on "new fuzzing tools on the ksmbd and smb code ... simple to set up and test locally with virtual machines". — [Phoronix](https://www.phoronix.com/news/Greg-KH-Clanker-Linux-Bugs)
- Daniel Stenberg, FOSDEM 2026 (LWN, 16 Feb 2026): AI tools found "more than 100 bugs that had been missed by other methods"; "machines don't get bored and they don't get tired"; curl now "work[s] with several AI-powered analyzing tools" internally with "a clever human in the loop"; AI-proposed patches were consistently inferior to human-written fixes. — [LWN](https://lwn.net/Articles/1058266)
- curl closed its HackerOne bug bounty on 31 Jan 2026 (secondary sources). — [Neowin](https://neowin.net/news/beloved-tool-curl-is-shutting-down-its-bug-bounty-over-ai-slop-reports); [Pinggy](https://pinggy.io/blog/curl_ai_slop_summer_of_bliss/)
- FreeBSD's Alpha-Omega project: AI for "vulnerability discovery and analysis only, all patches will be manually created"; "Security Team's access to publicly available AI models and tokens will be provided free of charge". — [Phoronix](https://phoronix.com/news/FreeBSD-AI-Bug-Discovery)
- Google: the goal is "shifting from identifying open source security threats to solving them"; CodeMender is "AI agent for code security" from DeepMind. — [Google blog](https://blog.google/innovation-and-ai/technology/safety-security/ai-powered-open-source-security/)
- CISA (Jul 2026): "agencies should automate dependency management and patch management workflows. Automated workflows for applying and testing patches can be a part of a continuous integration/continuous delivery (CI/CD) pipeline." — [CISA PDF](https://www.cisa.gov/sites/default/files/2026-08/open-source-software-security-principles-and-practices.pdf)
- OSS-CRS/AIxCC: "seven teams built such systems and open-sourced them after the competition. However, all seven open-sourced CRSs remain largely unusable outside their original teams"; ATLANTIS "discovered 10 previously unknown bugs (three of high severity) across 8 OSS-Fuzz projects". — [arXiv 2603.08566](https://arxiv.org/pdf/2603.08566); [Georgia Tech news, 21 Apr 2026](https://news.research.gatech.edu/2026/04/21/competition-community-how-team-atlantas-ai-cybersecurity-breakthrough-going-open-source)

### Inferences
- [interpretation] The un-met layer is "fix shipping": patch validation, regression testing, stable-branch backport generation and release automation for small projects. The funders describe it (Google, CISA, LF) but none names an open-source tool that does it for arbitrary projects; CodeMender is not open source as far as this research found.
- [interpretation] Local-model auditing harnesses (kres is 23 stars) are immature relative to the demand signal from the kernel; a web/security developer could build the equivalent for web stacks (JS/TS, Python, PHP) where OSS-Fuzz coverage is thin.

### Gaps
- No verbatim statement from the kernel or curl names a specific missing tool; the needs above are inferred from what they adopted (local models, kres, initial-fix requirement).
- Whether CodeMender or Sec-Gemini have open-source releases was not verified.

## Key Question 5: Consolidated "wanted" list with build-status checks (14 items)

### Takeaway
Of 14 funder-named capabilities, five are already served by healthy projects where contribution beats competition (OSS-CRS, OSS Rebuild, osv.dev, vexctl, cbomkit), five are thinly served or fragmented (fix-shipping automation, local-model audit harness, CRA compliance tooling for stewards, Trusted Publishing onboarding spec/test suite, security-contact discovery), and four are specification-plus-reference-implementation jobs with a named WG audience (package-repo threat model, Binary Transparency guide/spec, PURL-in-CVE lookups, OpenEOX end-of-support tooling).

### Cited Findings
Format: capability; funder quote and URL; programme and money; window; already built (GitHub health on 22 Oct 2026).

   - Funder/programme: OpenSSF AI/ML WG Cyber Reasoning Systems SIG (sandbox project); Alpha-Omega funds the use of such tooling (FreeBSD USD 250k) — [Phoronix](https://phoronix.com/news/FreeBSD-AI-Bug-Discovery). Alpha-Omega Q4 window open to 31 Oct 2026; next opens 1 Jan 2027.
